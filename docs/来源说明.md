# 自研边界与设计约束说明

> 本文件说明本项目的自研边界，以及"为什么有这些设计约束"。
> 建立日期：2026-09-28

---

## 一、自研边界

本项目从"要做什么"（产品功能边界）到"怎么做"（技术方案、数据模型、接口契约、算法）全部独立完成。

**代码 100% 自研**：不复制任何第三方代码、配置或数据库结构。

| 项 | 说明 |
|---|---|
| 后端 | Python 3.13 / FastAPI，独立设计 |
| 前端 | Vue 3 + TypeScript + Tailwind，独立设计 |
| 数据模型 | 见 `docs/architecture.md` §3：金额用整数分、成员唯一性用部分唯一索引 |
| 接口契约 | 见 `docs/architecture.md` §5 |
| 分摊算法 | 均分 + 最大余额法（`backend/app/services/split.py`） |
| 配置与容器 | `.env.example` / `docker-compose.yml` / CI 配置均为独立编写 |
| 文档 | 全部独立撰写 |

## 二、设计约束从哪来

本项目的安全约束不是凭空列的，而是来自**该领域广为人知的常见缺陷**。这些缺陷在同类型 Web 应用中反复出现，与具体是哪个项目无关。

我们把它们逐条转成了硬约束，纳入 P0 验收：

| 常见缺陷 | 本项目约束 | 对应验收 |
|---|---|---|
| 身份靠前端传参（`?userId=` 之类）导致越权 | 身份只从服务端 Token 解析，接口不收身份入参 | C1、C2 |
| JWT 密钥硬编码在源码 | 密钥仅来自环境变量，缺失即启动失败 | C3、A2 |
| 数据库账号口令明文入库，`.gitignore` 未忽略配置文件 | 只提交 `.env.example`，`.env` 被忽略 | A2、A4 |
| CORS `allowedOrigins("*")` | 白名单走环境变量，永不使用 `*` | C4 |
| 上传目录匿名可访问，用户上传文件进了版本库 | 上传目录不匿名可枚举；上传文件不入库（V1 不做上传，C6 标 N/A） | C6 |
| 测试几乎为零，回归无保障 | 核心链路 + 越权均有自动化用例 | B1、B2、C1 |

## 三、一句话

本项目的价值主张是"**一条可被自动化验证的多人协作账目链路**"——它证明的是工程判断，不是功能数量。
上面这张表就是工程判断的清单：每一条都能指向一个可执行的验收编号。
